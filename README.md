# CloudCodex

## 下载站点

下载站点的静态文件独立放在 `website/`：`website/index.html` 为首页，`website/Resources/` 为网页使用的资源。页面可直接打开，无需构建；部署时将 `website/` 内的内容放到站点根目录，保留目录结构。

根目录的 `Resources/` 继续存放 Mac 应用的图标和资源；网页使用的图标副本随下载站点独立维护。

点击工具栏的信息按钮，或菜单栏「CloudCodex → 关于 CloudCodex」，打开独立的只读介绍窗口。介绍涵盖工作区与会话管理、消息与附件、执行设置、个性外观、远程控制，以及本机 app-server 的请求与事件流原理。

## Build 53：远程模型一致性

- Mac 心跳同步 `defaultModel` / `defaultEffort`。小程序使用已同步设置，在提交时写入具体值；服务端在设备锁内为旧客户端补齐空值，缺少快照时要求明确选择，不再创建未固定设置的新任务。
- 任务 `model` / `effort` 是提交设置，`actualModel` / `actualEffort` 仅来自该任务 `turnId` 的本地执行记录，通过运行状态、最终状态和重连补传同步。缺失实际记录时显示“尚未同步”，不从会话标题或当前输入框推断。
- Mac 实时气泡使用本轮设置，读到已核实的实际设置后只更新同一 `turnId` 的内容。相同提问的不同轮次不会互相覆盖。
- 重试保留提交设置，清空原任务的实际模型与轮次；新任务入队后切换 Mac 模型不改变其设置。升级前已存在的空设置队列保留原语义，不批量修改或重跑。
- 升级需同时部署 go-ai、运行 Build 53，并更新小程序。旧 Mac 未同步默认值时，仍可明确选择模型和推理强度提交。

- 对话内容使用原生 Markdown 排版，支持标题、列表、引用、代码块、表格、链接与图片
- 提问和会话摘要不展示自动附带的浏览器上下文包装；保留实际提问的 Markdown、图片附件及用户正文中的标题，不修改原始会话记录

- 每条 Codex 回复显示该轮实际使用的模型和推理强度，历史切换模型后也不会混淆
- 每个提问显示发送时间，每个回答显示该轮完成时间

- 继续现有会话并实时查看 Codex 回复
- 会话空闲且输入框为空时，通过 Codex 的临时预测分支（`thread/fork`、`experimentalPredictionMode`）获取续问建议，并以灰色提示显示。按 Tab 或点击「Tab 采纳建议」后填入草稿，可继续编辑再发送；开始输入、有附件、任务执行中或等待回答时不显示。预测使用原会话的模型与上下文，可能消耗模型额度，并经过现有额度保护；分支不持久保存、不混入会话列表或原任务消息，完成或取消后解除订阅。建议按会话和上一轮隔离，预测不可用时回退为普通输入框。
- 支持图片和文件附件，带缩略图预览与移除
- 动态读取 Codex 模型，并选择模型、对应推理强度以及标准/加速响应速度
- 加速选择作为全局偏好保存在本机，影响后续请求；切换会话、刷新列表或恢复旧会话不会用历史速度覆盖该选择。输入栏独立显示闪电「加速」标识；当前模型不支持加速时显示「标准」。
- 支持只读、工作区、完全访问三种权限模式
- 支持 macOS 原生中文语音输入

- 远程控制开启并由 AI 小程序扫码配对后，约每 60 秒只读获取 Codex 账号额度，经设备心跳同步到小程序；按真实窗口展示套餐到期时间、5 小时/每周及其他额度、额外额度余额、恢复时间、可用重置次数和到期明细。Mac 端可逐条确认后使用重置次数；远程同步不包含账号标识、凭据或可兑换的原始重置 ID
- 已配对的 Mac 可在远程控制面板确认解绑；存在排队或执行中的远程任务时服务端拒绝解绑，成功后自动生成新的限时二维码供原账号或其他账号重新绑定，不删除 Mac 文件、本地会话或历史任务
- 复用 Codex Desktop / CLI 的本机登录、模型和配置，无需另外填写 API Key

## 本机监控与卡顿诊断

会话的滚动位置修正在布局通知结束后合并执行；切换会话、卸载旧视图后，旧连接的待执行回调失效。

长回复按最终可用宽度排版，原生滚动条占用空间后可以收缩，避免切换会话时内容横向撑大滚动区域。

工具栏的 CPU、存储和温度读取在串行后台队列执行；系统服务响应慢时保留上一份读数，不阻塞窗口，也不堆积重复采样。刷新间隔仍使用偏好设置中的选择。

应用运行时会检测主线程心跳。连续约 3 秒没有响应时，自动使用 macOS `sample` 抓取 2 秒原生线程栈到 `~/Library/Logs/CloudCodex/ui-hang-1.sample.txt`（以及编号 2、3）。每次启动最多抓取 3 份，后续启动按相同文件名覆盖；目录权限 0700，文件权限 0600。记录仅用于本机诊断，不上传，不记录对话正文、请求参数或服务进程 stderr。系统统一日志的 `com.zhengyuntao.cloudcodex` / `responsiveness` 分类记录监测启动与心跳超时。若进程已被终止且未曾抓到栈，仅靠重启后的采样不能确认上一次卡死原因。

“周额度换算与套餐对比”已移除，包括两个界面入口、自动采样、换算记录操作及专用采样进程。正常的套餐额度刷新、重置时间和使用统计保留。旧版保存在本机的换算历史不再读取或更新，本次移除不会清除这些偏好数据。

### 套餐名称

套餐名称统一显示为 `Pro 100`（接口 `prolite`）、`Pro 200`（`pro`）、`Pro 500`（`promax`）；账号管理、套餐与额度、使用统计共用同一映射。历史采样中的 `Pro 5×` / `Pro 20×` 在显示和连续采样比较时兼容为新名称，保留原始存储及接口字段，不改变额度或费用计算。对应档位参考 [OpenAI 官方定价](https://learn.chatgpt.com/docs/pricing)及官方客户端的套餐标识。

### 多账号管理与切换

入口：工具栏「账号管理」、菜单「账号 → 账号管理…」或「套餐与额度 → 账号管理」。点击「添加账号」，在官方浏览器授权页完成 ChatGPT 登录；成功后显示账号、套餐、最近一次读取的额度及更新时间。添加不会切换正在使用的账号，需点击卡片上的「切换」。账号列表和当前选择会在重启后保留。

原有环境保留为「本机默认账号」，继续使用进程继承的 `CODEX_HOME` 或 Codex 默认目录。新增账号使用 `~/Library/Application Support/CloudCodex/Accounts/<UUID>` 作为独立 `CODEX_HOME`，启动参数设置 `cli_auth_credentials_store="keyring"`，凭据由 Codex 存入 macOS 钥匙串，应用偏好设置仅保存 UUID、邮箱和套餐。应用不复制、导出登录令牌，也不覆盖本机默认账号的凭据。登录通过 `account/login/start`，完成通知后再用 `account/read` 核验；取消使用 `account/login/cancel`。

切换会重新启动 CloudCodex 自己的 app-server 子进程，并核验目标账号；失败时尝试恢复原连接。所有账号共用会话、收藏和未读标记；切换保留当前会话 ID、历史消息、草稿和附件，新连接重新取得该会话的写入权后可继续下一轮。额度和统计记录仍按账号区分，切换时重建采样起点。工作区目录组织、外观、第三方厂商配置和远程设备配对保持为应用公共设置。新增目录不会复制本机默认目录的 config、MCP 或技能文件；账号目录下的技能与通用 `~/.agents/skills` 按 Codex 自身规则发现。当前若使用第三方模型，账号切换不改变模型厂商，使用 ChatGPT 套餐需在模型设置选择 OpenAI。

切换前需等待运行中、重试中及排队的任务结束（不在运行途中强制更换身份），远程控制可保持开启：切换时暂停轮询并等待本轮同步结束，完成后自动恢复，后续工作使用共享会话及当前账号的登录身份。后台轮询不显示阻塞横幅，也不反复禁用切换按钮；点击切换后若正在领取任务或处理远程命令，按钮保持显示等待状态，最多等待 15 秒，超时才提示重试。重新授权当前账号前先切回「本机默认账号」；若授权得到不同邮箱，会退出该次错误登录并保留原卡片，另一个账号应通过「添加账号」保存。移除仅适用于非当前的新增账号，确认后先 `account/logout` 再移除卡片，本地会话文件保留。

会话共享使用本机默认 `CODEX_HOME` 的 `sessions`、`archived_sessions` 和 SQLite 状态库：新增账号的两个会话目录链接到共享目录，app-server 通过 `sqlite_home` 指向同一状态库。旧账号目录先合并会话文件，再整体改名为 `*.before-sharing-<UUID>` 备份；同名分叉内容会停止迁移并保留原文件。列表启用 Codex 的 rollout 扫描以发现迁入记录。认证目录、钥匙串条目和账号配置不共享、不复制。旧账号的收藏/未读记录只合并一次，原偏好备份保留。

新增账号使用钥匙串后，旧的仅从 `auth.json` 读取的头像或订阅到期字段可能不可用；界面不回退读取其他账号的资料。额度卡片明确标注采样时间，网络或登录失败时保留旧快照并显示错误。验证使用 `swift test --filter CodexAccountsTests` 的模拟子进程，覆盖授权提前完成、取消后迟到通知、共享会话续接、失败回退、保留草稿/运行中任务阻止切换、远程控制开启时切换及失败回退保持开关及退出移除；真实浏览器登录、钥匙串授权和多账号模型调用需交互验收。

### 自动刷新

在「偏好设置（个性设置）→ 会话与显示 → 套餐与额度」中配置自动刷新频率，可选 10 秒、30 秒、1 分钟（默认）、2 分钟或 5 分钟。修改后立即按新间隔重新计时，设置自动保存，重启后继续使用。套餐面板中的「刷新」按钮仍可立即读取最新信息；启动、重连和网络恢复也会触发检查。常规刷新同时更新账号接口连接状态。

额外额度保护启用且有任务运行或处于额度保护暂停状态时，仍每 5 秒检查一次；发送前检查、额度变更事件和使用重置次数后的刷新保持原有行为。因此实际更新可能快于这里选择的常规间隔。此设置用于 ChatGPT 套餐，不改变第三方服务商计费或远程控制的额度同步周期。

## 构建与运行

### 额外额度保护

「个性设置 → 执行保护 → 允许使用额外额度」默认关闭，并持久保存选择。
顶部和套餐详情中的「剩余额度」读取 `account/rateLimits/read` 的 `credits.balance`，与套餐周期百分比、可用重置次数分开显示。

开关关闭时，每次 `turn/start` 和 `turn/steer` 提交前都重新读取额度。明确检测到任一已返回的套餐窗口耗尽或额外额度余额下降时，保护会锁定发送，向 CloudCodex 已跟踪及已发现的运行会话发出 `turn/interrupt`，停止容量重试和等待消息投递，保留等待消息与历史。额度读取失败、数据缺失或无法确认时不触发限制；读取错误保留在额度详情中。旧版本仅因无法确认数据而保存的保护状态会在启动时自动清除。额度变更通知触发只读刷新；有运行任务时还约每 5 秒检查一次。暂停失败会显示数量并继续重试，不能当作已经暂停成功。

触发原因跨重启保留。打开允许开关可解除保护；也可在顶部提示点击「检查套餐额度并解除保护」，仅在所有已返回窗口都有已知剩余额度且没有未完成的暂停时解除。解除后等待队列可继续投递，已中断的回合需要手动继续。

检查期间按钮显示「正在检查套餐额度…」并禁用重复点击；若仍有套餐周期耗尽、无法确认额度或读取失败，结果直接显示在保护提示区。检查确认额度恢复后，保护提示区消失。

这是客户端保护，不是服务端禁止扣费。当前本机 app-server 的提交协议未提供禁止使用余额的参数；额度更新和中断都存在延迟，无法撤销检测前已经发生的消耗，也不能保证阻止其他独立客户端的账号消耗。检测账号余额下降会保守暂停 CloudCodex 的会话，不将扣费归因到某个具体会话。测试使用模拟余额与中断回调，不发起真实扣费任务。

## 内置浏览器

工具栏的地球按钮展开会话右侧浏览器。支持标签页、地址输入、返回、刷新以及直接手动操作。网页使用 WebKit，登录数据使用 CloudCodex 专属持久化 profile，不继承 Edge/Safari 登录。标签页按任务隔离，最多每任务 8 页、全 App 24 页；关闭 App 后标签页不恢复，网站登录数据保留。

新建会话通过 app-server 的实验性 `dynamicTools` 注册 `cloudcodex_browser`，模型可打开 HTTP/HTTPS 页面、读取可见文字及元素、点击、填写、滚动、截图、返回和关闭。显式指定外部浏览器时仍可使用原插件。已有会话的工具由 app-server 原样恢复；要使用此工具请新建会话。小程序新建的任务复用同一创建链路。

元素编号每次读取重新生成，旧编号及其他任务的标签页请求会被拒绝。工具不提供任意 JS、Cookie、密码读取或系统文件访问；密码和文件输入需要用户手动操作。跨域 iframe、Canvas 内部控件及复杂网页登录弹窗尚不提供完整自动化支持。网页新窗口链接在当前标签页打开，非 HTTP/HTTPS 外部应用链接不自动启动。

验证：`CLOUDCODEX_BROWSER_TEST=1 swift test --filter EmbeddedBrowserTests` 运行 WebKit 表单、截图与隔离测试；另设 `CLOUDCODEX_BROWSER_MODEL_TEST=1` 可运行实际模型的动态工具闭环（会创建一个本地测试会话并消耗模型额度）。

## 远程控制与钥匙串授权

远程控制面板支持「内置服务」和「自定义服务」。自定义服务填写 HTTPS 根地址（可含路径前缀），无需使用内置小程序；后端需兼容现有 agent 协议。先关闭远程任务并等待当前操作结束，再保存地址。各服务使用独立设备 ID 和钥匙串密钥，切回原地址复用原身份，切换不自动解绑原服务。原有内置服务的设备 ID、钥匙串记录和配对保持兼容。

面板提供「查看接入说明」「查看 API 文档」「复制完整 AI 指引」和 Markdown 导出。完整 AI 指引内含固定 Agent API、参考 Mini API、字段 Schema、任务状态机、数据库最小结构、服务号通知、错误语义和分层验收清单。内置模式使用自建地址占位符，只有已保存的自定义服务地址才会带入；内置服务地址不会写入自建文档。内容不含设备密钥、配对码或本地工作区数据。仓库文档见 [自定义远程控制接入指引](docs/remote-control-integration.md)、[API 文档](docs/remote-control-api.md) 和 [OpenAPI 3.1](docs/remote-control-openapi.yaml)。初版自建后端可让历史和额度重置队列返回成功 `data:null`，优先完成注册、配对、心跳、任务领取、状态回传、通知事件与解绑。

远程控制关闭时不会访问设备密钥。开启后的自动连接只在后台进行一次不弹窗的读取；需要授权、被拒绝或取消时，远程连接暂停，刷新和轮询不会重试。请在“远程控制”面板点击“授权钥匙串并连接”主动授权。本地会话不受影响。

设备密钥仍保存在登录钥匙串中；只有明确确认记录不存在且用户主动连接时才会创建。授权失败不会删除、覆盖已有凭据，也不会修改钥匙串访问控制。

本机开发构建默认使用固定的 Apple Development 身份，使 macOS 能在更新后继续识别同一个 App，并保留钥匙串授权。其他 Mac 没有该证书时，可通过 `make app CODESIGN_IDENTITY='自己的代码签名身份'` 覆盖。切换签名身份后的首次启动仍需授权一次；本项目不会自动创建证书、更改系统信任或向其他应用开放钥匙串。

## 电脑控制应用授权

通过 `cua_repl` 控制 DataPilot、微信开发者工具等本机应用时，CloudCodex 会以发起该轮任务时实际提交的权限为准：完全访问任务会自动允许本次会话使用目标应用，并在执行记录中显示“完全访问已自动授权电脑控制”；工作区、只读或无法确认权限的任务仍显示目标应用、Bundle ID 和调用工具，让用户选择仅本次会话允许、始终允许（服务支持时）或拒绝。60 秒内未确认会自动取消，使任务明确失败而不是一直停在工具调用中。切换会话或在任务执行中更改权限菜单，不会改变已经运行任务的授权判断。

## 队列恢复（Build 49）

远程心跳返回本设备未结束任务的会话/轮次标识，Mac 在后台只读核对对应轮次。只有明确返回 `completed`、`interrupted` 或 `failed` 才补传结束状态；`notLoaded`、读取失败、找不到轮次和运行时间长都不会触发失败或重放任务。同会话仍串行执行。

Build 54 起，小程序任务还会与本机正在执行的任务串行领取；远程任务结束后，CloudCodex 会退订未在桌面选中、没有等待消息或容量重试的会话。这样每次任务仍可按需恢复原会话，但不会让旧任务的 `cua_repl` 和辅助功能观察者长期累积，避免多个远程会话同时争用原生电脑控制桥接。

Build 55 起，电脑控制超时与崩溃保护同时识别旧版 `dynamicToolCall` 和新版 `mcpToolCall` 事件。当 Sky 原生桥接返回 `native pipe closed before response` 时，CloudCodex 会停止当前轮次、向小程序回传明确失败原因、释放远程会话，并暂停领取新任务 60 秒，避免对同一应用连续绑定造成崩溃风暴；工具详情也会显示失败输出，而不再只显示调用参数。

Build 56 起，用户消息底部的编辑操作、模型/推理强度和时间使用自适应页脚：空间足够时保持一行，窄窗口下整组换行；模型胶囊和时间始终保持单行，避免模型名称被压成竖排。

结束/重新排队状态先进入本地待补传记录，成功确认后才删除，网络中断或重启后继续补传；其中不保存设备密钥。服务端恢复操作校验设备、所有者、会话和轮次，保留已有执行过程与文件差异；普通结束上报不再被较新的进度版本丢弃。

需同时部署 go-ai 的 `runningTasks` 心跳及 `recovery` 状态上报支持。旧服务端仍可领取和上报任务，但不能自动发现升级前遗留的未结束任务。协议参考：[Codex App Server](https://learn.chatgpt.com/zh-Hans/docs/app-server)。

只读实机核对（不会发送任务、恢复会话或改写远程状态）：

```bash
CLOUDCODEX_RECOVERY_THREAD=已有会话ID \
CLOUDCODEX_RECOVERY_WORKSPACE=/实际授权工作区 \
CLOUDCODEX_RECOVERY_TURNS=已结束轮次ID1,已结束轮次ID2 \
swift test --filter RemoteRecoveryTests.testOptInReadOnlyRecoveryProtocol
```

## 公平调度（Build 52）

远程调度使用独立的全局最近会话快照，不再使用当前选中工作区的列表。切换工作区、清空列表或浏览其他会话不会改变后台心跳的调度依据。对外部 writer 冲突保留短期忙碌状态，不再清掉其他任务的本机执行记录。

go-ai 对忙碌会话设置 30 秒持久冷却，并只允许同会话最早的排队任务参与领取；等待中的会话不挡住其他空闲会话，冷却结束后自动重新检查，同会话保持提交顺序。旧 Mac 的重新排队上报也能触发保护。心跳的可选 `queueSummary` 在 Mac 展示实际排队数，小程序通过 `waitReason`、`waitMessage`、`queuePosition` 与 `retryAfter` 区分会话忙、同会话排队及设备离线。

任务领取、进度上传和全局快照刷新各自单路后台执行，慢请求不再堵住心跳与恢复。此升级不取消、不重复提交现有任务；服务端发布后现有队列直接使用新调度规则。

`writer_busy` 单独表示另一 Codex 进程持有会话写入权限，不能等同于“当前轮次仍在执行”。小程序显示“等待 Codex 释放会话”；即使上一轮完成，原进程也可能仍占用会话。不会删除锁文件、强制接管或结束原进程。

## 运行要求

- macOS 14 或更高版本
- 已安装 ChatGPT/Codex 桌面版，或 `codex` 命令行工具
- Codex 已完成登录

应用优先使用 `/Applications/ChatGPT.app/Contents/Resources/codex`，也会检查 Codex.app、Homebrew 和当前 `PATH`。

同一个持久会话同一时间只能有一个写入端。如果某个会话正在 Codex 主应用中执行，控制台仍可读取它，但需要等原任务结束或关闭后才能接管并继续发送。


## 自定义模型服务商

偏好设置分为「外观与背景」「会话与显示」「模型服务商」「执行保护」四个标签页。可拖动窗口边缘调整大小；尺寸自动保存在本机，关闭后重新打开及重启应用后恢复。恢复时限制在当前屏幕可用范围内，窗口最小内容尺寸为 640×480。

「偏好设置 → 模型服务商」分别保存 OpenAI、DeepSeek、阿里云百炼和火山引擎方舟配置。第三方卡片可填写各自的 API Key、Base URL 和多个模型 ID、显示名称及每个模型的推理档位，启用后出现在对话菜单；「启动默认服务商」单选决定下次启动使用的厂商。对话菜单为全局选择，影响所有对话的后续请求。OpenAI 沿用本机 Codex 登录与配置，自动读取模型目录，也可补充模型 ID 和推理档位。阿里云默认 Token Plan，火山默认 Coding Plan，也可选择按量计费。阿里云按量地址和火山按量模型须从控制台复制。保存当前厂商的配置不用退出应用；修改启动默认不会切换当前厂商，停用当前厂商时才切换到默认厂商。地址和套餐区别见 [服务商接入说明](docs/model-providers.md)。

对话的「模型设置」可先选厂商，再选择模型和推理强度，点击确定后生效。同一家切换用于下一轮；跨厂商切换会在任务及队列空闲时重连本地 Codex 服务，并在继续会话时使用原有上下文。旧版单厂商配置自动迁移到同一厂商卡片，保留原地址、模型和钥匙串账户，不覆盖其他厂商。第三方模型选项使用 `provider:<厂商>:<模型 ID>` 作为界面 ID，实际请求仍使用原始模型 ID；远程端继续接受当前厂商的原始模型 ID，且只公布当前厂商模型以避免误路由。

- 三家的接入使用 **Responses API**，需要支持流式响应和工具调用。阿里云仅支持 Chat Completions 的 Coding Plan 暂不支持；可选择 Token Plan 或支持 Responses 的按量模型。
- API Key 保存在 macOS 钥匙串。非敏感设置保存在 CloudCodex 偏好中，密钥通过子进程环境变量传入；不写入共用的 Codex 配置，不放入进程命令参数，并从命令工具的环境中排除该变量。
- 「测试连接」只读取服务商 `/models`，不会发送模型生成请求。通过测试表示模型列表接口可访问，不代表 Responses、工具调用、图片或其他能力已经验证；没有 `/models` 的兼容服务仍可保存配置。
- 第三方模式使用填写的模型 ID，DeepSeek 默认推理强度 `high`，阿里云和火山默认 `medium`；按服务商生成独立模型目录和工具配置，不使用加速服务。密钥按服务商、接入方式和地址分别保存。ChatGPT 套餐额度和额外额度保护不适用于第三方，费用与额度由服务商管理。
- 「使用统计 → 第三方 API」支持按服务商、模型及时间范围查看本机 Token 用量、已记录响应次数和任务完成情况，重启后保留。未回报用量的失败重试和其他客户端请求不能完整计入；准确请求数、费用及余额以服务商控制台为准。
- 配置仅通过 CloudCodex 启动 app-server 的覆盖参数生效。切换后继续已有会话，会将其上下文交给当前服务商；更换服务商前应确认其数据处理政策。

### 红点会话筛选

左侧工作区列表中的“红点会话”入口显示已完成但未查看的会话数量，与 Dock 未查看计数使用同一状态。点击后可跨工作区查看并搜索红点会话，不受普通列表最近 60 条的限制。旧会话会按 ID 只读取摘要补全列表，摘要读取提示未加载时，继续翻页查找所有来源及归档会话；仅在完整查找确认记录不存在后清除残留红点，连接或查找失败时保留红点并提供“重试”；筛选和搜索不会清除红点，打开会话后沿用现有已读规则。即使关闭普通列表红点显示，该入口仍可使用。


### 小程序与 Mac 会话收藏同步

Mac 继续以 `cloudcodex.favoriteConversations.v1` 保存收藏；升级兼容仅含 `snapshots` 的旧数据，并在同一记录中保存最近处理过的收藏操作 ID，避免确认失败重试覆盖后续本地操作。小程序发来的操作是明确设置 `favorited`，不会触发开发任务、恢复会话或发送消息。

远程心跳新增 `supportsFavorites: true` 及 `threads[].isFavorite`。原有最多 300 条调度快照保留，额外补充最多 300 条不在近期快照中的收藏，只同步远程授权工作区。快照之外的收藏使用未知执行状态，避免把历史状态当作当前状态。

Mac 通过 `GET /api/cloud-codex/agent/favorites/next` 领取收藏操作，校验设备、有效期及真实会话工作区后写入现有收藏，通过 `POST /api/cloud-codex/agent/favorites/{id}` 回传 `applied`/`failed`。操作不晚于 2 分钟过期；新客户端连接旧后端时，此可选接口失败不会中断任务执行。

配套 go-ai 和 mp-ai 需要一同升级。先部署后端的表结构和接口，再安装新版 Mac 并上传小程序；编译和单元测试不能替代双方点击收藏/取消的真机同步验收。

### 本人设备间账号共享

Mac 与 Windows 的账号管理均可为已登录本地账号生成一次性分享码，供自己的另一台 Mac 或 Windows 配对。来源设备更新短期访问凭据，接收端通过现有后端读取加密更新；长期续期凭据留在来源设备。需要两端客户端与 go-ai 支持 account-shares 接口，当前源码完成不代表线上服务已升级。使用、协议、撤销语义和验证边界见 [设备账号共享](docs/account-device-sharing.md)。

### 双向设备账号共享

Mac 与 Windows 均可在账号管理生成分享码，并在另一台自己的电脑「账号管理 → 通过分享码添加账号」连接。支持 Mac ↔ Windows 及同平台设备间共享，沿用同一个后端与 `CCS1` 协议。Mac 接收后新增共享账号卡片，手动切换使用；移除前先切换到其他账号。来源电脑需保持应用运行以更新短期凭据，长期续期凭据留在来源电脑；接收账号不再转分享。详见 [配对与持续更新](docs/account-device-sharing.md)。

## 自定义启动动画

在「偏好设置 → 外观与背景 → 启动动画」中开启播放或导入 GIF。默认关闭；导入成功会自动开启。支持预览、恢复默认应用图标动画、设置 1–10 秒显示时长，以及点击「跳过」或按 Esc 结束播放。每次应用进程启动仅播放一次，重新打开窗口不会重复播放；应用服务在后台正常初始化。

GIF 限制为 20 MB、600 帧、每帧最大 2048 × 2048 像素，导入文件复制到本机 Application Support/CloudCodex/Personalization/startup.gif，移动原文件不影响播放。导入失败保留已有动画；保存的文件不可用时回退到默认动画。系统开启「减少动态效果」时显示静态画面。这是 CloudCodex 应用启动画面，不修改 macOS 开机画面或登录启动设置。

### 远程任务普通文件（2026-10-26）

远程心跳新增 `supportsFiles:true`；任务可包含 `files:[{id,name,size}]`，最多 4 个，每个 20 MB。Mac 向当前设备的任务附件接口换取临时下载 URL，不向 OSS 发送设备密钥，不跟随下载重定向。下载到授权工作区中新建的 `.cloudcodex-attachments-<UUID>/<fileID>/<name>`，通过既有 ComposerAttachment 的 `mention` 传给 Codex。输入文件保留供后续会话使用；失败的本次下载目录会清理。

任务完成和读取会话历史时，将助手 Markdown 链接中明确交付的工作区文件私有上传至现有 go-ai/OSS，并返回 `cloudcodex-file:<uuid>` 引用。每条消息最多同步 8 个、单个 20 MB；排除目录、工作区外文件、隐藏路径（本功能管理的输入附件目录除外）、常见私钥文件和代码示例。未同步的路径保留，手机提示电脑端查看。已从小程序传入的附件在历史中保留其文件 ID，不暴露下载缓存路径。复制下载地址由小程序按需获取，有效期 1 小时。

先部署支持文件接口及 schema 的 go-ai，再更新本客户端，最后上传 mp-ai。自托管服务也需实现新增接口才能接收普通文件；现有纯文字与图片协议保留兼容。测试使用本地模拟网络，不代表已安装客户端、真实 OSS 或手机端下载通过。
