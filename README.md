# CloudCodex

## 关于 CloudCodex

点击工具栏的信息按钮，或菜单栏「CloudCodex → 关于 CloudCodex」，打开独立的只读介绍窗口。介绍涵盖工作区与会话管理、消息与附件、执行设置、个性外观、远程控制，以及本机 app-server 的请求与事件流原理。

执行中继续发送的消息进入本会话等待队列，任务结束后按顺序发送；也可点击「立即引导」补充当前执行轮次。介绍页同时说明模型与权限边界、远程控制前提，以及本地等待队列在退出应用后不保留的限制。窗口使用系统语义颜色，跟随应用外观，内容可滚动和复制；版本信息从当前应用包读取。

## Build 53：远程模型一致性

- Mac 心跳同步 `defaultModel` / `defaultEffort`。小程序使用已同步设置，在提交时写入具体值；服务端在设备锁内为旧客户端补齐空值，缺少快照时要求明确选择，不再创建未固定设置的新任务。
- 任务 `model` / `effort` 是提交设置，`actualModel` / `actualEffort` 仅来自该任务 `turnId` 的本地执行记录，通过运行状态、最终状态和重连补传同步。缺失实际记录时显示“尚未同步”，不从会话标题或当前输入框推断。
- Mac 实时气泡使用本轮设置，读到已核实的实际设置后只更新同一 `turnId` 的内容。相同提问的不同轮次不会互相覆盖。
- 重试保留提交设置，清空原任务的实际模型与轮次；新任务入队后切换 Mac 模型不改变其设置。升级前已存在的空设置队列保留原语义，不批量修改或重跑。
- 升级需同时部署 go-ai、运行 Build 53，并更新小程序。旧 Mac 未同步默认值时，仍可明确选择模型和推理强度提交。

应用已包含原生 macOS `.icns` 图标：蓝色玻璃质感的层叠会话终端，源文件与完整尺寸图标集位于 `Resources/`。

一个 macOS 14+ 原生 SwiftUI 客户端，通过本机 Codex app-server 读取和控制当前 Codex：

- 按工作文件夹查看所有现有会话
- 文件夹按需加载最近 60 个会话，不再一次读取全部历史会话
- 搜索、打开并读取会话历史
- 会话列表使用统一行高：单行标题、两行摘要、底部工作区/模型/时间；选中时增强文字对比，避免长摘要更新造成选中背景裁切
- 工作区标题旁的“＋”可新增本机文件夹；新增目录会持久保留，即使尚未创建过 Codex 会话也会显示
- 打开会话时只读取最近 20 个回合，避免超长会话阻塞界面
- 会话区默认显示最近 12 段内容（提问、执行过程、回答），不再按原始工具事件截断提问；超长回复按 8,000 字符分页，较早内容可按批加载
- 对话执行中实时显示思考摘要、计划、命令、文件变更、工具调用、网页搜索和协作任务
- 任务运行期间在最新区域持续显示“思考中”状态，完成后自动消失
- 高频流式事件合并后每 0.5 秒刷新；连续的处理事件合并为一个默认收起的“执行过程”，保留回复与事件顺序，不跨提问或已知回合合并
- 执行过程展开后在最多 320 点高的独立区域内滚动；步骤默认收起，按需显示详情，命令日志按 8,000 字符加载更多，不因流式结束自动关闭正在阅读的详情
- 执行过程摘要显示活动数量、当前思考/执行状态及失败提醒；本轮过程位于末尾时合并“思考中”提示，避免重复大卡片
- 对话内容使用原生 Markdown 排版，支持标题、列表、引用、代码块、表格、链接与图片
- 提问和会话摘要不展示自动附带的浏览器上下文包装；保留实际提问的 Markdown、图片附件及用户正文中的标题，不修改原始会话记录
- 流式回答与思考摘要也使用 Markdown 排版；实时预览限制为约 6,000 字符，并在后台解析
- 新建任务发送后保持选中，列表自动发现新增会话；会话切换保留未刷新的输出和后台处理记录
- 最近一轮的处理记录通过 `thread/items/list` 分页恢复，每页 24 项，后续仅重读末页和新增记录；不以只有提问/回答的摘要代替过程
- 推理菜单使用 Codex 默认可见档位并按模型能力过滤：轻度、中、高、极高、Ultra（支持持续模式的模型还显示“持续”）；不展示 `max` / 最高，历史记录仍保留实际强度
- 每条 Codex 回复显示该轮实际使用的模型和推理强度，历史切换模型后也不会混淆
- 每个提问显示发送时间，每个回答显示该轮完成时间
- 输入框支持直接按 `⌘V` 粘贴截图或复制的图片，并自动加入图片附件预览
- 使用与 Codex 一致的主界面任务编辑器新建会话，可选择工作文件夹并在首条消息中粘贴图片或添加文件
- 继续现有会话并实时查看 Codex 回复
- 支持图片和文件附件，带缩略图预览与移除
- 动态读取 Codex 模型，并选择模型、对应推理强度以及标准/加速响应速度
- 支持只读、工作区、完全访问三种权限模式
- 支持 macOS 原生中文语音输入
- 任务执行中可以从发送按钮直接停止
- 所选模型临时容量不足时保留原回合、执行过程和文件变更，按指数退避持续发起安全的“继续上一轮”请求；普通权限、参数、额度和代码错误不会被误判为无限重试
- 远程控制开启并由 AI 小程序扫码配对后，约每 60 秒只读获取 Codex 账号额度，经设备心跳同步到小程序；按真实窗口展示套餐到期时间、5 小时/每周及其他额度、恢复时间、可用重置次数和到期明细。Mac 端可逐条确认后使用重置次数；远程同步不包含账号标识、凭据或可兑换的原始重置 ID
- 已配对的 Mac 可在远程控制面板确认解绑；存在排队或执行中的远程任务时服务端拒绝解绑，成功后自动生成新的限时二维码供原账号或其他账号重新绑定，不删除 Mac 文件、本地会话或历史任务
- 复用 Codex Desktop / CLI 的本机登录、模型和配置，无需另外填写 API Key

## 内置浏览器

工具栏的地球按钮展开会话右侧浏览器。支持标签页、地址输入、返回、刷新以及直接手动操作。网页使用 WebKit，登录数据使用 CloudCodex 专属持久化 profile，不继承 Edge/Safari 登录。标签页按任务隔离，最多每任务 8 页、全 App 24 页；关闭 App 后标签页不恢复，网站登录数据保留。

新建会话通过 app-server 的实验性 `dynamicTools` 注册 `cloudcodex_browser`，模型可打开 HTTP/HTTPS 页面、读取可见文字及元素、点击、填写、滚动、截图、返回和关闭。显式指定外部浏览器时仍可使用原插件。已有会话的工具由 app-server 原样恢复；要使用此工具请新建会话。小程序新建的任务复用同一创建链路。

元素编号每次读取重新生成，旧编号及其他任务的标签页请求会被拒绝。工具不提供任意 JS、Cookie、密码读取或系统文件访问；密码和文件输入需要用户手动操作。跨域 iframe、Canvas 内部控件及复杂网页登录弹窗尚不提供完整自动化支持。网页新窗口链接在当前标签页打开，非 HTTP/HTTPS 外部应用链接不自动启动。

验证：`CLOUDCODEX_BROWSER_TEST=1 swift test --filter EmbeddedBrowserTests` 运行 WebKit 表单、截图与隔离测试；另设 `CLOUDCODEX_BROWSER_MODEL_TEST=1` 可运行实际模型的动态工具闭环（会创建一个本地测试会话并消耗模型额度）。

## 远程控制与钥匙串授权

远程控制关闭时不会访问设备密钥。开启后的自动连接只在后台进行一次不弹窗的读取；需要授权、被拒绝或取消时，远程连接暂停，刷新和轮询不会重试。请在“远程控制”面板点击“授权钥匙串并连接”主动授权。本地会话不受影响。

设备密钥仍保存在登录钥匙串中；只有明确确认记录不存在且用户主动连接时才会创建。授权失败不会删除、覆盖已有凭据，也不会修改钥匙串访问控制。

本机开发构建默认使用固定的 Apple Development 身份，使 macOS 能在更新后继续识别同一个 App，并保留钥匙串授权。其他 Mac 没有该证书时，可通过 `make app CODESIGN_IDENTITY='自己的代码签名身份'` 覆盖。切换签名身份后的首次启动仍需授权一次；本项目不会自动创建证书、更改系统信任或向其他应用开放钥匙串。

## 电脑控制应用授权

通过 `cua_repl` 控制 DataPilot、微信开发者工具等本机应用时，CloudCodex 会以发起该轮任务时实际提交的权限为准：完全访问任务会自动允许本次会话使用目标应用，并在执行记录中显示“完全访问已自动授权电脑控制”；工作区、只读或无法确认权限的任务仍显示目标应用、Bundle ID 和调用工具，让用户选择仅本次会话允许、始终允许（服务支持时）或拒绝。60 秒内未确认会自动取消，使任务明确失败而不是一直停在工具调用中。切换会话或在任务执行中更改权限菜单，不会改变已经运行任务的授权判断。

## 队列恢复（Build 49）

远程心跳返回本设备未结束任务的会话/轮次标识，Mac 在后台只读核对对应轮次。只有明确返回 `completed`、`interrupted` 或 `failed` 才补传结束状态；`notLoaded`、读取失败、找不到轮次和运行时间长都不会触发失败或重放任务。同会话仍串行执行。

Build 54 起，小程序任务还会与本机正在执行的任务串行领取；远程任务结束后，CloudCodex 会退订未在桌面选中、没有等待消息或容量重试的会话。这样每次任务仍可按需恢复原会话，但不会让旧任务的 `cua_repl` 和辅助功能观察者长期累积，避免多个远程会话同时争用原生电脑控制桥接。

Build 55 起，电脑控制超时与崩溃保护同时识别旧版 `dynamicToolCall` 和新版 `mcpToolCall` 事件。当 Sky 原生桥接返回 `native pipe closed before response` 时，CloudCodex 会停止当前轮次、向小程序回传明确失败原因、释放远程会话，并暂停领取新任务 60 秒，避免对同一应用连续绑定造成崩溃风暴；工具详情也会显示失败输出，而不再只显示调用参数。

Build 56 起，用户消息底部的编辑操作、模型/推理强度和时间使用自适应页脚：空间足够时保持一行，窄窗口下整组换行；模型胶囊和时间始终保持单行，避免模型名称被压成竖排。

结束/重新排队状态先进入本地待补传记录，成功确认后才删除，网络中断或重启后继续补传；其中不保存设备密钥。服务端恢复操作校验设备、所有者、会话和轮次，保留已有执行过程与文件差异；普通结束上报不再被较新的进度版本丢弃。

需同时部署 go-ai 的 `runningTasks` 心跳及 `recovery` 状态上报支持。旧服务端仍可领取和上报任务，但不能自动发现升级前遗留的未结束任务。协议参考：[Codex App Server](https://learn.chatgpt.com/zh-Hans/docs/app-server)。

只读实机核对（不会发送任务、恢复会话或改写远程状态）：

```bash
CLOUDCODEX_RECOVERY_THREAD=已有会话ID \
CLOUDCODEX_RECOVERY_WORKSPACE=/实际授权工作区 \
CLOUDCODEX_RECOVERY_TURNS=已结束轮次ID1,已结束轮次ID2 \
swift test --filter RemoteRecoveryTests.testOptInReadOnlyRecoveryProtocol
```

## 公平调度（Build 52）

远程调度使用独立的全局最近会话快照，不再使用当前选中工作区的列表。切换工作区、清空列表或浏览其他会话不会改变后台心跳的调度依据。对外部 writer 冲突保留短期忙碌状态，不再清掉其他任务的本机执行记录。

go-ai 对忙碌会话设置 30 秒持久冷却，并只允许同会话最早的排队任务参与领取；等待中的会话不挡住其他空闲会话，冷却结束后自动重新检查，同会话保持提交顺序。旧 Mac 的重新排队上报也能触发保护。心跳的可选 `queueSummary` 在 Mac 展示实际排队数，小程序通过 `waitReason`、`waitMessage`、`queuePosition` 与 `retryAfter` 区分会话忙、同会话排队及设备离线。

任务领取、进度上传和全局快照刷新各自单路后台执行，慢请求不再堵住心跳与恢复。此升级不取消、不重复提交现有任务；服务端发布后现有队列直接使用新调度规则。

`writer_busy` 单独表示另一 Codex 进程持有会话写入权限，不能等同于“当前轮次仍在执行”。小程序显示“等待 Codex 释放会话”；即使上一轮完成，原进程也可能仍占用会话。不会删除锁文件、强制接管或结束原进程。

## 运行要求

- macOS 14 或更高版本
- 已安装 ChatGPT/Codex 桌面版，或 `codex` 命令行工具
- Codex 已完成登录

应用优先使用 `/Applications/ChatGPT.app/Contents/Resources/codex`，也会检查 Codex.app、Homebrew 和当前 `PATH`。

同一个持久会话同一时间只能有一个写入端。如果某个会话正在 Codex 主应用中执行，控制台仍可读取它，但需要等原任务结束或关闭后才能接管并继续发送。
